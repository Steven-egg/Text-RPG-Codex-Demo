# 四職業點數式角色成長 v1

目的：記錄本次玩家裸體成長的唯一資料來源（SSOT）、換算、節點驗收與量測結果。範圍只涵蓋 `JOBS`、裸體 `get_stats` 與直接傷害的敏捷浮動；不變更怪物、裝備、技能、聖物、存檔 schema、GUI、地城、補給或 S10 情境。

## SSOT 與公式

`04_data/data/jobs.py` 的每個職業只保存 `growth_points`；舊的 `growth` 和 `extra_every_3` 已移除，兩套制度不會疊加。封版後的總點數不是四職業一致值：劍士是使用者核定的 13.50 點例外，其餘三職業維持 15.00 點。

- 每升一級：劍士 13.50 點；法師、盜賊、牧師各 15.00 點。
- 每三級里程碑：從同一張主表程式化計算 `per_three_level_points = growth_points / 3`；劍士合計 4.50 點，其餘職業各 5.00 點。不保存第二張獨立數值表。
- 等級計數：`level_bonus = level - 1`，`milestone_count = floor((level - 1) / 3)`。
- 單一裸體屬性：`base + rate * per_level_points * level_bonus + rate * (per_level_points / 3) * milestone_count`。
- 點數兌換：HP `2`；MP、物攻、魔攻、物防、魔防、敏捷 `1`；暴擊、效果命中 `0.1`（個百分點）。
- `get_stats` 保留浮點數供戰鬥計算；沒有為顯示預先截斷。既有 CLI 直接顯示該值，必要的整數化仍只在原有的回復、傷害或 buff 邊界使用 `ceil` / `floor`。

## 敏捷：直接傷害限定

`direct_damage_roll` 先決定直接傷害浮動，暴擊仍在後續由既有暴擊機率與倍率處理：

- 一般浮動：`uniform(0.80, 1.10)`。
- 靈巧高傷機率：`min(30%, agility * 0.15%)`。
- 靈巧高傷浮動：`uniform(1.15, 1.45)`。

使用 `random.random() * 100 < chance`，所以 30 敏捷是 4.5%、100 是 15%、200 及以上是 30% 上限。此函式僅由 `calc_typed_damage(..., direct=True)` 使用；DoT、固定投擲物與非直接傷害都沒有進入該路徑。

## 驗收與量測觀察

Focused test `06_tools/test_job_growth_points.py` 驗證劍士主表合計 13.50、其餘三職業各 15.00，里程碑表必為各自主表除以 3、五個指定節點公式、舊欄位不存在、效果命中邊界，以及敏捷 0/30/100/200 與 30% 封頂。`06_tools/validate_data.py` 使用逐職業固定總額，不再假設四職業都必須是 15.00。

既有 S10 與 B4 量測只作歷史診斷；回合數、耗材、品質比較與傷害比例都不構成怪物、補給或職業數值調整的授權。平衡已封版，只有可重現且影響正常通關或職業體驗的玩家問題，才可另開維護修正。

剩餘風險：小數裸體值現在會出現在 CLI 與 CSV；這是避免偷偷截斷的刻意結果。若後續需要特定 UI 格式，必須獨立決定顯示精度，且不可改變 `get_stats` 的原始計算值。歷史量測差距留作診斷紀錄，不預設下一輪平衡工作。
