# 《元素迷宮：邊境冒險者》擴大版遊戲架構

版本：architecture draft v0.1  
目的：作為 v1 playable vertical slice 之後的遊戲系統擴張藍圖。  
限制：此文件只描述架構與設計方向，不要求立即 code 施作。

## 1. 架構目標

目前遊戲已具備最小核心循環：城鎮、商店、合成、魔法書、兩座迷宮、戰鬥、任務、Boss 與存檔。下一階段的目標不是立刻增加大量內容，而是先定義可長期擴張的遊戲架構，避免之後每新增一座迷宮、一個職業或一種狀態都變成臨時硬寫。

擴大版架構要支援：

- 更多迷宮與元素環境。
- 更多素材、裝備、魔法書與合成配方。
- 職業轉職與職業專屬成長。
- 更清楚的任務鏈與章節推進。
- Boss 對策、抗性裝、特殊道具與迷宮準備度。
- data、schema、registry、validation 的長期維護。

## 2. 設計原則

### 2.1 玩家永遠要有下一個可理解目標

每個階段都應清楚回答玩家的問題：

- 我現在該去哪裡？
- 我缺什麼準備？
- 這趟迷宮就算沒通關，能帶回什麼？
- 我回城後能把資源轉成什麼戰力？
- 下一個系統或迷宮什麼時候解鎖？

### 2.2 迷宮不是單純關卡，而是資源產地

每座迷宮都要有自己的資源價值：

- 特定素材。
- 特定元素環境。
- 特定敵人掉落。
- 對應合成裝備。
- 對應工會任務。
- 對應 Boss 對策。

### 2.3 失敗也要推進

遊戲不應讓玩家因一次探索失敗而完全停滯。迷宮失敗應保留部分收益，讓玩家理解「還沒準備好」，而不是「我浪費時間」。

### 2.4 城鎮是資源轉化中心

城鎮不是休息選單，而是玩家把迷宮收益轉化成戰力與進度的地方。每個城鎮功能都應對應一種轉化：

- 商店：金幣 → 補給與基礎裝備。
- 工匠：金幣與素材 → 裝備強化。
- 合成屋：迷宮素材 → 抗性裝、職業裝、Boss 對策。
- 魔法商店：金幣與素材 → 永久技能。
- 工會：素材與 Boss 戰果 → 任務獎勵與迷宮解鎖。
- 神殿：章節成果 → 轉職資格。

## 3. 核心遊戲層

擴大版遊戲可分為六個核心層：

```text
玩家狀態層
→ 城鎮整備層
→ 迷宮探索層
→ 戰鬥驗證層
→ 資源轉化層
→ 章節解鎖層
```

### 3.1 玩家狀態層

管理玩家當前能力與長期成長。

包含：

- 等級與經驗。
- HP、MP、攻擊、防禦、敏捷、暴擊、元素抗性。
- 職業與未來轉職。
- 裝備欄位。
- 背包與素材。
- 已學技能。
- 任務與解鎖狀態。

未來擴張：

- 職業熟練度。
- 裝備熟練度。
- 元素親和。
- 被動技能。
- 多套裝備配置。

### 3.2 城鎮整備層

管理所有回城後的玩家決策。

目前 v1 城鎮功能：

- 冒險者工會。
- 鐵刃工坊。
- 堅甲工坊。
- 旅人小鋪。
- 米菈合成屋。
- 星燈魔法商店。
- 轉職神殿。
- 倉庫與背包。

未來擴張方向：

- 鍊金攤：製作高階消耗品、元素藥劑、異常解除道具。
- 情報屋：用金幣購買迷宮提示、Boss 弱點、稀有素材情報。
- 訓練場：測試技能、教學狀態異常、挑戰鏡像戰。
- 委託板：每日/週期性材料任務，提供刷素材方向。
- 遠征準備：出發前選擇補給包、抗性策略、探索目標。

### 3.3 迷宮探索層

迷宮負責產出素材、金幣、經驗、裝備、任務物與章節關鍵道具。

每座迷宮應定義：

- 推薦等級。
- 主要屬性。
- 步數或樓層長度。
- 事件權重。
- 怪物池。
- 素材池。
- 陷阱類型。
- 特殊事件。
- Boss 或精英怪。
- 通關獎勵。
- 解鎖條件。
- 推薦準備。

未來迷宮應分成三類：

| 類型 | 用途 | 範例 |
|---|---|---|
| 資源迷宮 | 刷素材、金幣、經驗 | 青苔洞窟 |
| 對策迷宮 | 要求抗性、道具或特定技能 | 焦石礦坑、冰雪遺跡 |
| 試煉迷宮 | 驗證職業、轉職或章節成果 | 鏡像試煉、轉職神殿深處 |

### 3.4 戰鬥驗證層

戰鬥負責驗證玩家準備是否足夠。

目前規則：

- 回合制。
- 玩家攻擊與傷害技能 100% 命中。
- 防禦可降低傷害。
- 技能消耗 MP。
- 道具可回復、逃脫或施加 debuff。
- 敵人有基礎攻擊與少量特殊行動。

未來戰鬥應支援：

- 更完整元素相剋。
- 更多狀態異常，例如凍結、中毒、沉默、破甲、灼傷、麻痺。
- 敵人 behavior key，而不是每個特殊怪都硬寫在 engine。
- Boss 階段設計。
- 戰前準備影響戰鬥難度。
- 職業專屬技能循環。

戰鬥設計重點不是讓命中懲罰玩家，而是讓玩家透過準備、抗性、技能與道具做出正確對策。

### 3.5 資源轉化層

所有素材都應至少有一個用途。

資源類型：

- 金幣。
- 經驗。
- 普通素材。
- 稀有素材。
- 裝備。
- 魔法書素材。
- 工會任務物。
- 元素印記。
- Boss 掉落。

素材用途：

- 合成裝備。
- 強化裝備。
- 學習魔法書。
- 交付任務。
- 解鎖迷宮。
- 解鎖轉職。
- 製作 Boss 對策道具。

未來每新增素材時，都應同步確認：

- 掉落來源。
- 至少一個消耗出口。
- 是否參與任務或合成。
- 是否有稀有度定位。

### 3.6 章節解鎖層

章節解鎖負責讓遊戲有長期推進。

目前 v1 結尾：

- 擊敗山寨頭目葛倫。
- 取得血跡地圖。
- 取得火之印記碎片。
- 開啟第二幕元素迷宮伏筆。

未來章節應採「系統 + 迷宮 + Boss + 轉化」的節奏：

```text
新迷宮開放
→ 玩家吃到環境壓力
→ 回城取得新對策
→ 打通迷宮
→ Boss 掉落章節物
→ 工會/神殿解鎖下一系統
```

## 4. 內容階層規劃

### 4.1 v1：邊境冒險者資格

狀態：目前已完成最小垂直切片。

核心內容：

- 青苔洞窟。
- 焦石礦坑。
- 工匠街。
- 魔法書。
- 合成屋。
- 山寨頭目葛倫。
- 血跡地圖。

目的：

- 教玩家核心循環。
- 讓玩家理解裝備與素材轉化。
- 開出元素迷宮主線。

### 4.2 v1.5：城鎮系統補強

目標：讓城鎮整備更像遊戲中樞。

建議新增：

- 鍊金攤。
- 情報屋。
- 訓練場。
- 更多合成配方。
- 更明確的迷宮出發前準備摘要。

不急著新增大量迷宮，先讓現有循環更清楚。

### 4.3 第二幕：元素核心

目標：讓玩家正式進入「根據迷宮準備裝備與技能」的中期玩法。

建議迷宮：

| 迷宮 | 屬性 | 推薦等級 | 主要壓力 | 對策 |
|---|---|---:|---|---|
| 冰雪遺跡 | 冰 | 8-12 | 凍結、低溫傷害 | 防凍裝、火技能 |
| 潮汐水道 | 水 | 10-14 | 中毒、濕滑陷阱 | 解毒、雷/破甲道具 |
| 風蝕高塔 | 風 | 12-16 | 高敏敵人、命中壓力替代規則 | 迅步、反擊、防禦姿態 |

第二幕核心系統：

- 元素抗性裝備。
- 元素技能組合。
- 稀有素材合成。
- 工會主線揭露。
- 第一批職業分歧前置。

### 4.4 第三幕：轉職與真相

目標：讓玩家從「準備迷宮」進入「定義自己的角色玩法」。

建議內容：

- 暗黑地形。
- 龍宮。
- 鏡像試煉。
- 轉職神殿深處。
- 遠古巨龍。

轉職路線：

| 初始職業 | 轉職 | 核心玩法 |
|---|---|---|
| 劍士 | 元素騎士 | 物理攻擊搭配元素附魔與抗性姿態 |
| 法師 | 星詠者 | 高 MP、多元素連鎖、弱點爆發 |
| 盜賊 | 影行者 | 先手、陷阱、暴擊、資源偷取 |
| 牧師 | 聖印使 | 治療、防禦結界、印記淨化 |

### 4.5 通關後與二週目

目標：提供長期刷裝與高難挑戰。

可選系統：

- 高難度迷宮。
- 元素支柱重構。
- 稀有裝備詞綴。
- Boss 重戰。
- 限制條件挑戰。
- 二週目保留部分資料。

## 5. 系統邊界

### 5.1 data 應負責

- 職業數值。
- 道具與裝備資料。
- 技能與魔法書。
- 怪物與掉落。
- 迷宮配置。
- 任務與解鎖。
- 商店商品。
- 合成配方。

### 5.2 engine 應負責

- 玩家輸入。
- 選單流程。
- 戰鬥流程。
- 傷害與狀態計算。
- 背包與裝備操作。
- 任務交付流程。
- 迷宮事件抽取。
- 存檔與讀檔。

### 5.3 schema 應負責

- 欄位契約。
- 型別規則。
- 跨表引用規則。
- 新增資料時的維護規則。

### 5.4 validation 應負責

- 檢查 id 是否存在。
- 檢查引用是否合法。
- 檢查 unlock key 是否有來源。
- 檢查基礎欄位是否缺失。

## 6. 未來資料化優先順序

不是所有東西都要立刻資料化。建議順序如下：

1. Monster behavior key。
2. Item effect。
3. Shop metadata。
4. Dungeon event weights per dungeon。
5. Quest unlock condition。
6. Boss phase data。
7. Job advancement requirement。
8. Element interaction table。

每次只資料化一個主題，並同步更新 schema 與 validation。

## 7. Engine 拆分方向

目前 `03_engine/engine/game.py` 作為最小垂直切片可以接受。未來若繼續擴張，建議按以下順序拆分：

```text
game.py
→ ui.py
→ state.py
→ inventory.py
→ shops.py
→ crafting.py
→ quests.py
→ dungeons.py
→ combat.py
→ registry.py
```

拆分規則：

- 每次只拆一個主題。
- 拆分後 `element_maze.py` 必須仍可啟動。
- 拆分後 smoke test 與 validation 必須通過。
- 不趁拆分改 gameplay。
- data 不反向依賴 engine。

## 8. 新內容加入流程

未來新增一個主要內容時，建議按這個順序：

1. 在 `01_content` 補設計目的與玩家體驗。
2. 在 `02_schema` 確認是否需要新欄位。
3. 在 `04_data/data` 增加資料。
4. 更新 `registry.py` 或 validation 允許的新 id/key。
5. 實作 engine 行為。
6. 跑 validation。
7. 跑 smoke test。
8. 更新 README 的版本狀態或 roadmap。

此文件目前只完成第 1 步：架構與設計目的。
