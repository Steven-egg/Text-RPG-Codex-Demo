## 1. 第二幕設計目標

### 1.1 核心定位

第二幕是玩家從「邊境見習冒險者」進入「元素迷宮探索者」的階段。

v1 的焦石礦坑已經讓玩家初步理解火抗、防禦、補給與素材轉化的重要性。第二幕應將這個概念正式化，讓玩家明確感受到：

- 不同迷宮有不同元素壓力。
- 進入迷宮前需要準備對策。
- 素材、合成、魔法書、裝備、任務不再只是各自存在，而是共同支撐一條攻略路線。
- Boss 不是單純數值牆，而是檢查玩家是否理解對策。
- 轉職神殿從 v1 的預告功能，逐步變成中期目標。

### 1.2 第二幕第一輪成功標準

第二幕第一輪若實作，應達成以下體驗：

- 玩家能從工會或劇情提示理解「血跡地圖指向灰燼裂谷」。
- 玩家第一次進入灰燼裂谷時，感受到火元素環境壓力高於焦石礦坑。
- 玩家能透過回城整備降低探索壓力，例如合成火抗裝、購買元素藥劑、學習對應技能。
- 玩家即使未打通灰燼裂谷，也能帶回有用素材並推進準備。
- 玩家擊敗灰燼守衛與燼印鎮衛後，取得三枚火之印記碎片。
- 玩家經由工會與神殿查閱，理解三枚碎片是「未完成的火之印記核心」，它是未來正式聖物或元素主線的零組件，而不是當前可啟用的完整火印。

### 1.3 本階段不追求的目標

第二幕第一輪不應急著做：

- 不一次新增冰、風、水、雷等全部元素迷宮。
- 不正式開放完整轉職系統。
- 不實作多角色隊伍。
- 不導入大型技能樹。
- 不重構整個 `game.py`。
- 不處理 Element Decay。
- 不把 runtime data 遷移到 JSON/YAML。

## 2. 第二幕玩家節奏

### 2.1 章節節奏

建議第二幕第一輪採用七段式節奏：

| 階段 | 玩家狀態 | 內容目的 | 主要回饋 |
|---|---|---|---|
| 1. 血跡地圖回報 | 剛完成 v1 Boss | 承接 v1 結尾 | 工會指出地圖殘缺但可辨識方向 |
| 2. 灰燼裂谷線索 | 玩家取得新目標 | 建立第二幕主線 | 開放灰燼裂谷情報或偵查任務 |
| 3. 初次探索失壓 | 玩家進入新迷宮 | 展示火元素中期壓力 | 灼熱地形、火屬敵人、補給壓力 |
| 4. 回城準備 | 玩家理解自己尚未準備好 | 強化城鎮整備價值 | 合成、鍊金、情報、魔法書提示 |
| 5. 深入裂谷 | 玩家具備對策 | 驗證裝備與技能成長 | 更穩定推進、取得稀有素材 |
| 6. Boss 討伐 | 玩家面對灰燼守衛與後續燼印鎮衛 | 驗證火抗、補給、輸出循環 | 取得第 2 / 第 3 枚碎片 |
| 7. 神殿與教會回應 | 玩家回城查閱成果 | 連接未來火印與聖物伏筆 | 確認「未完成的火之印記核心」 |

### 2.2 玩家心理曲線

第二幕不應只提高數值，而應讓玩家經歷以下理解：

```text
我已經打倒葛倫，所以應該變強了
→ 新迷宮還是很危險
→ 原來這裡需要元素準備
→ 我可以用素材做出對策
→ 我再進去時推進更深
→ Boss 其實是在考我準備是否完整
→ 火之印記不是單純戰利品，而是轉職／主線鑰匙
```

### 2.3 建議推薦等級

| 內容 | 推薦等級 | 說明 |
|---|---:|---|
| 第二幕開場任務 | 6-8 | 承接打倒葛倫後的角色狀態 |
| 灰燼裂谷前半 | 7-9 | 第一次進入會有壓力，但不應必死 |
| 灰燼裂谷後半 | 9-11 | 需要火抗或更穩定補給 |
| 灰燼守衛 Boss | 10-12 | 驗證火抗、防禦、技能與回復配置 |
| 轉職試煉預告 | 10+ | 僅顯示條件，不正式開放完整轉職 |

## 3. 第二幕主線概要

### 3.1 劇情承接

v1 結尾玩家擊敗山寨頭目葛倫，取得血跡地圖與火之印記碎片。工會解讀後發現，血跡地圖並非普通藏寶圖，而是標記古代元素封印的殘缺路線圖。

圖上的第一個明確座標指向邊境東南方的乾裂谷地。那裡原本是廢棄採石區，但近年出現異常高溫、夜間火光，以及疑似人形守衛的目擊情報。

工會判斷：焦石礦坑的火之印記碎片，可能只是完整印記的一部分。若要理解山寨頭目葛倫背後的交易來源，必須追查灰燼裂谷。

### 3.2 第二幕主軸

第二幕第一輪主軸：

```text
追查血跡地圖
→ 收集火元素線索
→ 建立灰燼裂谷對策
→ 擊敗灰燼守衛
→ 追入燼印深窟並擊敗燼印鎮衛
→ 取得三枚碎片並確認「未完成的火之印記核心」
```

### 3.3 劇情調性

第二幕不需要沉重長篇劇情，仍以輕冒險、明確目標、NPC 提示為主。

建議敘事比例：

- 70% 玩法提示與目標推進。
- 20% 世界觀補充。
- 10% 角色對話與氣氛描寫。

劇情應服務 gameplay，不應讓玩家被長文本中斷核心循環。

## 4. 主迷宮：灰燼裂谷

### 4.1 迷宮定位

灰燼裂谷是第二幕第一個主迷宮，也是第一個「正式元素中期迷宮」。

| 項目 | 建議內容 |
|---|---|
| 迷宮名稱 | 灰燼裂谷 |
| 建議 id | `dungeon_ash_ravine`（已實作） |
| 屬性 | 火 |
| 推薦等級 | 偵查版已實作為 7-9；完整路線候選為 7-12 |
| 迷宮長度 | 偵查版已實作為 18 步；完整路線候選仍可評估 2 段式探索 |
| 主要壓力 | 偵查版為火屬普通怪與素材探索；Boss 蓄力攻擊仍未實作 |
| 對策方向 | 火抗裝備、降攻／破甲道具、MP 補給、防禦技能、回復藥 |
| 主要產出 | 已實作裂谷灰、焦黑鐵片、精煉火焰石；赤燼晶核、印記殘片仍未實作 |
| Boss | `boss` 已指向 `boss_ash_guardian`；灰燼守衛 MVP 已完成 |
| 通關成果 | 灰燼守衛後取得第 2 枚碎片並導向燼印深窟；完整火印不開放 |

難度註記：灰燼裂谷目前不因 Lv10、火抗 25%、裝備抗火斗篷的短測結果調整怪物數值。若要評估入口難度，應以 Lv7-9、低裝或無抗火斗篷狀態重新測試。

### 4.2 灰燼裂谷與焦石礦坑的差異

焦石礦坑是火元素入門壓力；灰燼裂谷是火元素中期驗證。

| 比較項 | 焦石礦坑 | 灰燼裂谷 |
|---|---|---|
| 功能 | 教玩家火抗概念 | 驗證火抗與中期準備 |
| 壓力 | 火傷偏痛，但仍可硬撐 | 火傷、灼熱地形、Boss 蓄力更明顯 |
| 對策 | 暖石墜、抗火斗篷、補給 | 火抗裝備、元素藥劑、技能循環、情報提示 |
| 素材 | 火焰石、小魔晶等 | 高階火素材與印記相關素材 |
| Boss | v1 結尾的山寨頭目 | 元素守衛型 Boss |
| 敘事 | 山寨與礦坑異常 | 古代元素封印與轉職伏筆 |

### 4.3 迷宮區段設計

灰燼裂谷可分為前半與後半，但第一輪不一定需要在 engine 實作分層。即使 runtime 仍是步數制，也可以在設計文件中先定義概念。

#### 前半：裂谷入口

目的：讓玩家感受到新迷宮壓力，但仍可撤退帶回素材。

可能事件：

- 遭遇火屬小怪。
- 撿到裂谷灰或焦黑鐵片。
- 熱風造成少量 HP 損失。
- 發現古代刻痕，提示火之印記與神殿有關。
- 發現被燒焦的營地，提示此地已有其他冒險者失敗。

#### 後半：熔痕古道

目的：要求玩家已經有一定準備，並導向 Boss。

可能事件：

- 遭遇灰燼騎士、熔岩蝙蝠等較高壓敵人。
- 取得赤燼晶核等稀有素材。
- 地形熱浪使長探索消耗增加。
- 觸發 Boss 前提示：空氣中的火光聚成守衛輪廓。

### 4.4 迷宮事件權重概念

此處只做設計概念。`dungeons.py` 已有灰燼裂谷偵查版，但尚未支援前後半分層事件權重。

| 事件類型 | 前半建議權重 | 後半建議權重 | 設計目的 |
|---|---:|---:|---|
| 戰鬥 | 40% | 50% | 保持核心壓力 |
| 素材 | 25% | 20% | 讓撤退也有收益 |
| 地形傷害 | 10% | 15% | 強化火元素環境 |
| 特殊線索 | 15% | 5% | 前半多給提示，後半收束 |
| 稀有事件 | 5% | 5% | 提供驚喜與高階素材 |
| 安全事件 | 5% | 5% | 避免連續壓力過高 |

## 6. 灰燼裂谷怪物規劃

### 6.1 怪物設計原則

灰燼裂谷怪物應比焦石礦坑更明確地承載火元素玩法，但仍避免一次導入過多新規則。

第一輪可先使用既有戰鬥能力能支援的行為：

- 普通攻擊。
- 火屬性攻擊。
- 蓄力提示後高傷害。
- 防禦較高但速度較慢的敵人。
- 速度高但血量低的敵人。

暫不強求完整 burn status、DOT、命中懲罰或複雜 AI。若 engine 尚未支援，可先以傷害與文字提示表現。

### 6.2 普通怪候選

| 建議 id | 名稱 | 定位 | 主要壓力 | 掉落方向 | 設計目的 |
|---|---|---|---|---|---|

## 7. Boss：灰燼守衛

### 7.1 Boss 定位

灰燼守衛是第二幕第一個元素守衛型 Boss。它不是一般山賊或野獸，而是古代火元素封印的殘留守護者。

| 項目 | 建議內容 |
|---|---|
| Boss 名稱 | 灰燼守衛 |
| 建議 id | `boss_ash_guardian` |
| 類型 | 火元素守衛 / 古代構裝 |
| 推薦等級 | 10-12 |
| 主要檢查 | 火抗、回復、MP 管理、防禦時機、破甲或爆發輸出 |
| 掉落 | 歷史候選曾列守衛餘燼、完整火之印記、赤燼晶核；目前 runtime 只給第 2 枚 `key_fire_mark_shard` |
| 劇情功能 | 證明火之印記與神殿試煉有關 |

### 7.2 Boss 戰設計目標

灰燼守衛應讓玩家理解：

- 火抗能明顯降低壓力。
- 防禦不是無用選項，應用於 Boss 蓄力回合。
- 補給不足會讓長戰鬥失敗。
- 破甲道具或攻擊技能能縮短危險時間。
- 擊敗 Boss 後應有明顯主線推進。

### 7.3 Boss 階段概念

第一輪 engine 若尚未支援 boss phase，可先把下列作為未來資料化方向，不必立即實作完整階段制。

| 階段 | HP 區間 | 行為概念 | 玩家對策 |
|---|---:|---|---|
| 第一階段：沉眠守衛 | 100%-70% | 普通攻擊、低頻火焰打擊 | 穩定輸出與觀察 |
| 第二階段：爐心點燃 | 70%-35% | 火焰攻擊頻率上升，偶爾蓄力 | 火抗、回復、適時防禦 |
| 第三階段：灰燼爆發 | 35%-0% | 蓄力後高傷害，攻擊更激烈 | 防禦蓄力、使用補給、爆發收尾 |

### 7.4 Boss 招式候選

| 招式 | 類型 | 效果概念 | 對策 |
|---|---|---|---|
| 灰燼重擊 | 物理 | 中高物理傷害 | 防禦、提升防具 |
| 火舌掃擊 | 火屬性 | 中等火傷 | 火抗裝、抗火藥劑 |
| 爐心蓄熱 | 蓄力提示 | 下一回合使用高傷害招式 | 防禦、補血、使用減傷道具 |
| 熔火爆裂 | 火屬性爆發 | 高火傷，應有明顯提示 | 蓄力回合防禦 |
| 餘燼護甲 | 防禦姿態 | 短暫提高防禦或降低受到傷害 | 破甲釘、魔法攻擊、等待結束 |

### 7.5 Boss 前提示

Boss 前應給玩家一次明確警告，避免玩家在完全不知情下被擊倒。

建議文本方向：

```text
裂谷深處的岩壁浮現赤紅紋路。
你手中的火之印記碎片開始發燙，像是在回應某個沉睡的東西。
前方傳來沉重的腳步聲。

你感覺若沒有足夠火焰抗性、回復道具與戰鬥準備，繼續前進會非常危險。
```

## 14. 驗收標準

第二幕第一輪若進入實作，驗收時不只看能不能跑，也要看流程是否維持可維護。

### 14.1 玩家體驗驗收

- 玩家知道打完葛倫後下一步要找工會。
- 工會能提示血跡地圖指向灰燼裂谷。
- 灰燼裂谷明顯比焦石礦坑危險，但不是無理秒殺。
- 玩家撤退仍能取得素材與準備方向。
- 玩家能透過合成、商店、技能或補給改善攻略成功率。
- Boss 前有警告。
- 擊敗灰燼守衛後有明確章節成果。
- 神殿能回應火之印記，提示未來轉職。

### 14.2 架構驗收

- 新增 id 不應散落在 engine 裡未登記。
- 新 unlock key 應集中於 registry。
- 新怪物、素材、任務、迷宮、配方應能被 validation 檢查。
- schema、data、README 不應互相矛盾。
- 不應為一個 Boss 大量硬寫特殊分支，除非有明確註解與後續資料化計畫。
- `element_maze.py --smoke-test` 應通過。
- `06_tools/validate_data.py` 應通過。

## 17. 總結

第二幕第一輪的重點不是內容數量，而是建立一個可重複的擴張方法。

灰燼裂谷應作為第一個驗證案例，驗證以下流程是否成立：

```text
內容文件
→ schema 檢查
→ registry / unlock key 規劃
→ data 最小新增
→ validation
→ engine 最小支援
→ smoke test
→ README / 文件同步
```

只要灰燼裂谷能用這條流程穩定完成，後續冰雪遺跡、潮汐水道、風蝕高塔、轉職試煉與第三幕內容，都可以用相同模式安全擴張。
