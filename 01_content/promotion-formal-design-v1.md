# 正式轉職設計與量測前置 v1

狀態：owner 已確認的規畫 SSOT；本文件不單獨授權 runtime、怪物數值或 GUI 實作。

## 1. 目的與範圍

正式轉職是一次、不可逆的二選一，目的在於讓角色在 Ice 後以不同
戰術解法完成 Earth、Thunder、Final；它不是第二套屬性成長、裝備
資格或元素系統。

- 轉職條件：完成 `quest_ice_return_handoff` 且角色達 Lv.18。
- 轉職地點：轉職神殿；兩條路線同時直接可選，不要求素材、裝備、
  額外任務或職業試煉。
- 保留 `state["job"]` 的基礎職業，另保存 nullable `promotion_id`。
  介面顯示「基礎職業／轉職稱號」。
- 每條路線在選擇當下取得一個新主動技能及一個被動；已學技能保留。
- 新主動一律消耗完整玩家回合。每條路線最多新增一個暫時戰鬥狀態。
- 不改裸體成長、裝備限制、品質規則、元素／聖物規則，也不開放重選。

## 2. 八條路線

數字均為下一輪固定種子量測的候選資料，未經 owner 簽核前不得調整
怪物數值以迎合它們。

| 基礎職業 | 轉職稱號 | 新主動的核心 | 被動核心 |
|---|---|---|---|
| 劍士 | 血鋒鬥士 | 扣最大 HP 百分比、有限堆疊的本戰血戰；收益集中於 Physical Charge 爆發。不得扣血致死。 | 深化血戰對 Charge 技能的收益。 |
| 劍士 | 血鎧守衛 | 扣最大 HP 百分比、有限堆疊的本戰血鎧；提高物防與魔防。不得扣血致死。 | 提高血鎧的防護容量／上限。 |
| 法師 | 星裂術士 | 從已學的火、冰、自然、雷元素中選一種，消耗高 MP 施放單次爆發。不得提供新元素或自動猜測弱點。 | 深化正確元素爆發的回報。 |
| 法師 | 印紋術士 | 從已學元素中選一種施加印記。 | 同元素命中時單次引爆並清除印記；不做多元素反應矩陣。 |
| 盜賊 | 斷影刺客 | 對低生命敵人的處決型物理技能。 | 深化低血目標的暴擊與收尾收益。 |
| 盜賊 | 瘴痕獵手 | 對已流血或中毒目標的利用型物理技能。 | 深化既有狀態收益；不消耗、不刷新狀態，也不越過種族無效規則。 |
| 牧師 | 聖幕司祭 | 建立固定值護盾。僅在它實際吸收直接傷害時，每個敵方行動最多反震一次。 | 提高護盾容量；不增加護盾耗盡後的再生或其他連鎖。 |
| 牧師 | 聖蝕司祭 | 一回合建立／刷新自身 Cleric DoT 與再生，並標記本戰第一瓶符合條件的聖蝕聖瓶。 | 再生與自身 DoT 並存時小幅強化 DoT；勝利後返還該瓶聖蝕聖瓶，不提高固定傷害。 |

## 3. 資料、存檔與介面契約

1. 正式 promotion data 必須有八筆，包含：`source_job`、稱號、摘要、
   共用資格、主動技能 ID、被動技能 ID 與候選數值設定。正式資料不得
   與 `JOB_SPECIALIZATIONS` 的 preview-only 用途混用。
2. state 需升版並加入 `promotion_id: str | None`。選定後不得由一般
   UI action 改寫或清除。
3. 舊存檔若 `job` 是「元素騎士／星詠者／影行者／聖印使」，遷移時還原
   對應基礎職業、清空轉職選擇；保留其他進度與已學技能，不自動指定
   新分支。
4. 移除 CLI 神殿直接覆寫 `state["job"]` 的舊轉職行為。
5. CLI 與 live GUI 共用 eligibility、選擇與 view-model helper：兩端都要
   顯示條件、兩條能力摘要、不可逆確認與已選結果；已選角色不可再顯示
   可選按鈕。

## 4. 實作順序

### A. S10 補給／報表對齊前置（獨立小切片）

先處理現行未提交補給改版造成的 S10 漂移：`item_potion_m` 已從 runtime
移除，但 `06_tools/s10_baseline_config.py` 的 `boss_standard` 仍把它放入
`sustain_hp`，使 `--s10` 及 `--s10-summary` 在 supply validation 失敗。

- Boss scenario 改為依各區可合法取得、符合五槽上限的 HP／MP／投擲物
  profile；普通怪 scenario 維持無補給。
- 範圍只限 S10 config、S10 measurement、S10 report 與對應 tests。
- 不藉此重寫 B4、Phase 0、戰術策略、怪物數值或轉職 runtime。
- 完成標準：S10 CSV、S10 summary、S10 report 皆可重現；維持 stdout-only、
  CSV/JSON parity、固定種子與全域資料／RNG 不污染。

### B. 正式轉職 runtime

S10 前置完成後，再新增 formal promotion data、state migration、神殿選擇
與八組技能／被動。數值必須集中在資料設定，不得散落在 `game.py`。

### C. 量測與數字簽核

新增獨立的固定種子 promotion scenario layer，使用相同基礎裝備、合法
補給與怪物資料，量測未轉職及八分支的 Earth／Thunder／Final 代表怪物與
Boss。報告至少包含勝負、玩家／敵方行動、最終 HP/MP、補給耗用與直接／
DoT／道具傷害來源。

先提出候選成本、層數、倍率、護盾與低血門檻，由 owner 簽核；在簽核前
不得調整怪物資料。簽核後才做最後的八分支終盤複測與必要怪物微調。
八支皆須可行，但不要求相同回合數、風險或補給耗用。

## 5. 驗收清單

- 轉職資格、不可逆選擇、既有技能保留、舊稱號遷移與 CLI／GUI parity。
- 血鋒／血鎧不可自殺、不可超過堆疊上限，戰後清除。
- 印記只由同元素引爆並立刻清除。
- 瘴痕不改變流血／中毒的種族有效性，也不消耗或刷新它們。
- 聖幕反震只在護盾實際吸收直接傷害時觸發，且每敵方行動最多一次。
- 聖蝕聖瓶只在指定條件的勝利後返還一次；不影響其他補給或固定傷害。
- S10 對齊與 promotion scenario 均可重現，且不污染 runtime data、RNG 或存檔。

## 6. 本輪明確不做

- 第二次轉職、重選／洗轉職、職業試煉或分支素材門檻。
- 裸體成長、裝備資格、品質系統、元素附魔、聖物或怪物數值調整。
- 以舊 preview 名稱自動對映新分支。
- 在 S10 前置完成與候選數字簽核前開始正式轉職 runtime。
